- 既有主站在 `site/src/CommunityApp.vue` 中提供社区、CS2 日榜、玩家数据和反应测试。CS2 后端通过累计快照差分计算每日表现，不能把“每日战报”解释成逐场记录。
- 既有 `deploy/IDENTITY_PLAN.md` 记录稳定内部 ID 与 provider 映射方向，但整合标为“暂不实施”，且包含微信小程序 QR 过渡方案。
- 2026-10-08 本会话首先调查 OW 数据可行性，验证国服公共英雄统计可匿名读取；Overstats 个人战绩仍需要大神业务凭据，未用真实账号实测。
- 随后用户明确要求先制定并持久化计划，采用国服四项指标、近期平衡标签、OW 样式与头像，并预留注册用户对局与 KOOK 服务。

## D002：产品仅 web + KOOK

## D003：主站中明确区分 CS2 与 OW

**用户确认。** CS2 / OW 有独立入口、游戏内导航、类型、指标、头像和样式。共享 TrashBox 外壳与未来账号服务，不共享游戏统计含义。不得把 OW 接入独立 Radar `web/`，不得借此添加 Radar / Sniper 跨站导航。

## D004：先公共英雄数据，后个人对局

**设计采用。** 公共数据先形成可运行板块，不被账号依赖阻塞；个人数据在账号契约交付后独立上线。公开网页完成 P2 验收即可发布，不等待 P4/P5；KOOK 公共命令也不依赖用户映射。公共榜描述国服整体英雄表现；注册用户个人样本不代表国服整体，不用于替代官方榜。

## D005：近期平衡标签保留官方语义

**用户确认使用标签；设计采用多标签模型。** `enhances`、`weakens`、`adjusts` 分别映射增强、削弱、调整，不能由胜率涨跌推导。单英雄可同时出现在多组；保留官方日期与来源，不能将陈旧标签称作“本周更新”。

## D006：Overstats 的采集对象限制

**用户确认仅注册用户；设计采用验证绑定 + 明确授权。** 资格由服务端判断：站内有效注册身份、属于本人的 OW 国服绑定、允许同步、未撤销。禁止开放任意 BattleTag 查询入口、注册后抓取他人账号、抓取全服玩家或递归收集队友/对手。

上游返回其他玩家时，仅保存目标注册用户的指标和必要非身份对局元数据。不得保存其他玩家的昵称、BattleTag、头像、外部 ID 或整份包含这些信息的原始响应。其他已注册玩家也需各自有效绑定及同步授权，不能从一名用户的对局顺带采集。

## D007：账号设计由另一会话负责

**用户确认。** 本计划提出交接需求，不宣称知道另一会话的最终结果，不实现注册、OAuth、KOOK 绑定或账号合并。主键类型和外键迁移待正式契约确认；不将微信 OpenID、Steam ID、BattleTag 或群昵称充当稳定站内用户 ID。

## D008：网页路径兼容

**设计采用。** 首版保留查询参数路由，为新入口增加游戏维度。旧 `?view=rank` 和 `?view=stats&id=...` 默认归 CS2；不在没有 Nginx 协同修改时添加 `/ow/...` 深路径。

## D009：官方素材与 OW 视觉

**用户确认采用 OW 风格与英雄头像；设计采用来源清单。** 优先读取官网配置中的名称、头像与职责素材。用 OW 橙、冷灰、角色卡片等视觉语言形成独立主题，不把整站改成官方站，不照搬 CS2 图标。素材可访问性与使用范围分别记录；缓存或重新分发方式留给施工阶段核对。

## D010：快照、日期与统计口径

**设计采用。** 官方百分比保留为百分数值，KDA 保留来源值；未知公式、分母和样本数不得补造。源统计日期、补丁日期、抓取时间分列。趋势只来自真实存入的同口径快照；不将赛季累计指标差分为每日胜率，不补造历史。

## D011：权限与展示分开

**设计采用默认策略，最终账号产品契约待交付。** 注册不等于战绩公开；个人网页默认仅本人可见，KOOK 个人查询默认私信本人。公开展示和群消息需额外明确开启，采集授权与展示授权分别管理。撤销后立即停采、清理待执行任务并停止个人展示；存量删除期限由账号契约确定。

## D012：数据库与发布边界

**设计采用。** OW 使用独立 PostgreSQL 表，不改 CS2 数据模型；先在隔离测试库验证迁移与采集。现有本地脚本连接服务器数据库，不能直接用它验证写入。现有部分 Radar migration 是 MySQL 语法，不得复制。构建或 HTTP 200 不能替代业务响应校验及真实浏览器上线验收。

**设计采用，已完成本地验证。** 新鲜度以实际成功读取官网为依据，先读取当前元数据再取得同赛季 / 模式 / 段位的指标。失败时优先保留最近成功读取、口径完全匹配的已有数据，再使用匹配的打包快照，明确标记为历史并保留原获取时间；无匹配数据时显示无可用数据，不拿旧赛季指标填进新赛季标题，也不回退已确认的新赛季。页面可见时每 5 分钟检查，返回 / 聚焦时距上次尝试至少 30 秒才触发检查；刷新去重、卸载取消，保留正在检查 / 成功读取 / 历史降级的状态。
