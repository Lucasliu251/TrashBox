# OW 产品与界面设计

版本：首页设计 v1.1，2026-10-08。以用户反馈 D014 / D015 为当前首页依据；布局与优先刷新数据已完成本地验证，真实路径和逐版本证据见 `DEMO_V1.md`。全部英雄榜与简易详情属于 v1 历史实现，已退出当前首页。本文的独立页面、数据库、历史、个人战绩和 KOOK 仍是后续提案。

## 产品结构

TrashBox 保留共享站名、社区与未来账号入口；增加明确的 CS2 / 守望先锋选择。游戏名称在桌面顶部与手机导航中均可见，禁止继续让跨游戏入口只叫“排行”“数据”。

| 区域 | 内容 |
|---|---|
| 社区 | 现有文章、评论；首版不扩展帖子游戏分类模型 |
| CS2 | 现有排行、个人数据、反应测试，保留当前指标与视觉 |
| 守望先锋 | 国服指标摘要、近期调整完整头像名单、资讯轮播及高级信息占位；账号完成后再规划我的战绩 |

现有首页与旧 URL 保持兼容，不为 OW 重做整个社区首页。OW 入口先进入公共首页，匿名可查看指标摘要和近期调整。高级信息当前仅占位；个人入口的具体展示以后依据账号契约决定。

首版路径建议：

| 页面 | 查询参数 URL |
|---|---|
| 旧 CS2 日榜 | `/?view=rank`，继续有效 |
| 明确 CS2 日榜 | `/?game=cs2&view=rank` |
| 旧 CS2 玩家 | `/?view=stats&id=<steam_id>`，继续有效 |
| OW 公共首页 | `/?game=ow&view=heroes`，沿用 demo 已有入口 |
| OW 英雄详情 | 旧规划 `/?game=ow&view=hero&hero=<hero_key>`，当前首页不提供 |
| OW 近期调整 | 首页区域；独立 `/?game=ow&view=changes` 仍为旧规划 |
| OW 我的对局 | `/?game=ow&view=matches`，后续阶段 |
| OW 对局详情 | `/?game=ow&view=match&match=<local_id>`，后续阶段 |

每个游戏验证自己的 view/ID 类型。缺少 `game` 的历史链接按原行为解析；浏览器返回、前进、刷新与分享保持游戏入口。OW 当前首页清理已取消的筛选 / 详情 query；新增查询参数不能让旧 `id` 被误解为 OW 账号。需要 URL 筛选的未来页面另行设计。

## 当前公共首页（v1.1）

页面保留 OW 主题、手机 / 桌面响应式和当前匿名数据口径，依次展示资讯轮播、三项指标摘要、官方近期调整与高级信息占位。

- 顶部胜率 / 选取率 / 禁用率三项指标卡沿用 v1 展示与样式，不借本次修订更改默认统计含义；原详情动作改为打开官方英雄榜来源，避免留下无效交互。
- 默认读取当前赛季竞技全部段位。页面移除榜单筛选控件、清理旧筛选和详情 query，保留刷新能力及真实统计日期和来源。
- 近期增强、近期削弱、近期调整各占独立紧凑行，标题、来源日期与三行整体居中；每组完整显示所有英雄头像和可辨识名称，头像比 v1 增大。各行可按内容收缩，超过可用宽度自然换行，不设头像数量上限或“查看全部”才能展开的门槛。
- 原全部英雄榜单位置用“更多信息 / 内容待补充”的高级信息占位；不提供名称搜索、职责筛选、排序、完整英雄统计表或详情弹窗。
- 轮播保留视觉和切换控制，采用“版本更新 / 活动资讯 / 社区动态”三类未来内容的克制占位文案，标记示意配图；不编造活动、版本更新或发布日期。移除依赖英雄细节的操作按钮，不新增 CTA。

头像加载失败回退、减少动效、键盘可用性与来源日期要求继续适用。轮播与占位区域不增加注册、绑定或任意 BattleTag 查询动作。

### 数据检查与历史降级（D015）

打开页面时优先读取官方元数据，再取得当前赛季竞技全部段位指标；可见期间定期检查，返回页面时再次检查。显示真实成功检查状态，避免把构建快照描述为始终最新。刷新失败时仅使用元数据口径完全匹配的已有数据并明确标旧；新赛季无匹配数据则显示无可用指标，不能用旧赛季数值配新赛季标题。

源统计日期、官网标签日期和成功检查时间分别展示 / 记录。官网标签即使日期较旧，也保留源值；新抓取不能使其变成新补丁。定时检查须与页面可见性、卸载和请求取消协调，避免重叠刷新与切换 CS2 后写入 OW 状态。当前只读代理为本地开发能力，静态构建或上述流程不代表公网实时服务已部署。

## v1 英雄榜历史设计（不作为当前首页要求）

v1 原设计从上到下：

1. “守望先锋 · 国服”标题、赛季、官方数据日期与最近同步时间。
2. 模式 / 段位 / 职责筛选，英雄名称搜索与四项指标排序；名称搜索不查询玩家。
3. 近期调整摘要，可进入完整调整页；来源日期始终可见。
4. 桌面为可比较表格，手机为紧凑英雄卡片；两者信息顺序一致。

每行包含头像、中文名、职责、增强/削弱/调整多标签、胜率、出场率（官方选取率）、禁用率、KDA、详情入口。默认按胜率排序；缺失值显示“—”，不能改成 0。官网仅竞技显示禁用率，快速虽返回 0，UI 应显示“不适用”；不能把竞技零值也解释为不适用。

英雄数量来自当前有效数据，不写死 54。职责筛选采用该统计行的 `hero_type`，配置职责与统计职责冲突时记录异常，不能静默改值。按职责过滤不重算全体占比；不把多个段位的百分比简单平均成“全服”。

以上榜单与交互按 D014 从当前首页移除，保留此段用于理解 v1 的实现与数据语义，不能据此恢复榜单。竞技全部段位、Gold 和快速比赛已有历史实测；后续任何新统计口径仍需逐项验证。角斗领域参数在官方客户端可见，但数据结构和指标适用性需单独验收，不能因按钮存在就承诺全部指标。

## 英雄详情历史提案（当前首页已移除）

- 英雄头像、名称、统计职责、国服标识与官网来源入口。
- 当前筛选下四项指标，沿用榜单口径，不切换为个人战绩。
- 官方近期调整标签和来源日期；多个标签可并存。
- 从实际积累的快照显示胜率、出场率、禁用率、KDA 时间曲线；当前筛选无历史时说明“正在积累历史数据”。
- 切换赛季/模式/段位后重新选择可比曲线；不能将不同赛季拼接为连续同比。
- 详细技能/补丁正文仅在来源已确认时增加，不凭标签生成不存在的改动描述。

## 近期调整

展示官网的“近期增强”“近期削弱”“近期调整”三组英雄，包含头像、名称和官方记录日期。同一英雄可同时进入多个组；保留相同标签语义，无需通过详情页才能看到完整名单。

`patch_desc.date` 是标签来源日期，不等于数据统计日期。2026-10-08 观察到该日期为 2026/7/15，而英雄统计日期为 2026-10-07。页面应明确“官网标签记录于 …”，不得称其为今天/本周的新补丁，也不由抓取时间刷新“近期”含义。

## 个人战绩（依赖账号契约）

状态流：未登录 → 登录站内账号 → 绑定并验证本人 OW 国服账号 → 开启同步 → 首次同步 → 战绩展示。每步必须有独立状态；账号契约未就绪时显示“个人战绩接入中”，不提供假绑定或任意 BattleTag 查询。

我的战绩包含已同步范围、最后同步时间、胜负概况、角色/英雄使用、近期对局和同步/暂停入口。对局行显示地图、模式、日期、胜负和本人的英雄/指标。伤害、治疗、消灭、助攻、死亡是否存在以实测字段为准；零死亡情况不制造无穷大 KDA。

不套用 CS2 Rating、ADR、HSR 或能力雷达；官方英雄整体 KDA 与个人派生 KDA 分开说明。首版不新增未经验证的“实力分”“国服百分位”或跨职责综合排名。

详情仅展示目标用户的统计与必要地图、双方比分等非身份对局信息。未注册或未授权队友/对手不展示身份、不建立档案；不展示全员可点击名单。

## 视觉系统

| 部分 | 设计提案 |
|---|---|
| OW 强调色 | 橙 `#F59A23`；实际文字/按钮配色以可读性校验后定稿 |
| 背景 / 面板 | 深蓝灰背景、浅灰白卡片或浅色数据区域，避免照搬 CS2 黑金 |
| 信息色 | 冷蓝辅助；增强、削弱、调整各自颜色与文字/符号共同表达 |
| 轮廓 | 克制的切角、职责图标、英雄头像与清晰的表格；不用大量背景立绘压过数据 |
| 字体 | 系统中文字体为默认，数字使用等宽特性；不以未确认的官方字体为依赖 |
| 头像 | 官网配置中的 hero ID → 名称/头像；加载失败使用 OW 通用占位与英雄首字，不使用 CS2 Logo |

CSS 限定在 `.ow-section` / OW 组件作用域，主题变量独立；不得更改 CS2 全局配色。保持 TrashBox 品牌与非官方社区定位，素材用途/来源由 manifest 记录。

桌面至少验证 1280px，手机至少验证 390px 与 360px。链接与轮播控制支持键盘操作，头像有替代文本，按钮有焦点状态；调整组完整显示并自动换行，不依赖桌面宽度隐藏英雄。减少动效设置生效，未来图表必须提供文字数值。

## 数据状态与文案

- 首次加载：显示骨架与数据区域，不用演示数值伪装已上线。
- 无记录：区分筛选无数据、无历史、未同步与未授权。
- 上游维护 / 超时：保留最后成功快照，标注官方日期、同步时间与过期状态。
- 来源职责冲突：界面按当前统计口径展示，记录数据问题；避免把冲突资料用作确定的英雄身份结论。
- 调整日期过旧：保留官方标签并注明日期；不自行推断最新平衡方向。
- 未登录仅限制个人区域，不阻断公开英雄数据。
- 现有前端“小程序内使用”等文案仅在后续网页施工时清理/替换为真实 web 能力；不得为修文案修改小程序。

## KOOK（后续服务）

首批命令提案：英雄指标、近期调整、我的近期战绩、同步状态。公共命令可使用相同国服快照；个人命令必须解析账号会话交付的 KOOK → 站内身份映射，并复用网页权限与采集资格。

命令名、机器人仓库和推送频率尚未定稿。个人查询默认私信；群分享、日报订阅分别由用户开启。机器人不得通过群昵称、任意 BattleTag 或别人贴出的对局 ID 获取个人数据。不得将完整 Overstats 图片/卡片直接转发为首版个人回复，以免带出其他玩家资料。
